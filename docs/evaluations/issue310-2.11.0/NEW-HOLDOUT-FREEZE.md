# New synthetic holdout freeze

Freeze before execution: `new-holdout.json` contains two new synthetic cases for each issue, one English and one Korean, with original-code-point gold offsets and separate public spans. The previously committed `../accuracy-20261109/development-cases.json` is development data; no new holdout case belongs to those template groups. The same implementer authored both the candidate and these cases, so they are not independently blinded and do not establish generalization.

Run once: `uv run --locked --all-extras python docs/evaluations/issue310-2.11.0/replay_new.py OUTPUT_DIR`. The existing HTTP capture and scoring harness runs one baseline and one candidate request plus replay per case, with at most 60 seconds per arm. Store full raw captures and per-case comparison. Report exposed and partially exposed sensitive spans, public overmasking and exact restoration separately, with numerators and denominators; errors and unmeasured spans are not successes.

The fixed decision is hold unless no baseline-protected occurrence regresses, protection improves and the separate real-LLM comprehension screen also meets `../../EXPERIMENT_PROTOCOL_20261109.md`; unmeasured comprehension cannot satisfy adoption. For an interpreter screen use two repeats per task per arm, 16 interpreters and 16 separate graders per candidate, at most 32 total calls and 32,768 reported tokens per candidate, 600 seconds and 512/768 output tokens per interpreter/grader. Unknown failed-call usage stops further automated calls for that candidate. The already attempted previous screen counts toward this budget until usage is known. Cold/warm latency and RSS targets remain the original 1.25× baseline p95 + 5 ms and 32 MiB limits; do not infer a pass if not measured.
